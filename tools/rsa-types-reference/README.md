# RSA.Types complete source facade checkpoint

This new-only module family implements all five source types and five functions
of pinned crypton2.0.1 Crypto.PubKey.RSA.Types, including every declared instance.
It does not complete all crypton/Pandoc/calibre. Accepted arithmetic/X509 APIs are
unchanged. Blinder maps to accepted CryptoRsa.Blinder and Error to the five exact
accepted CryptoRsaOaep.Error identities; PublicKey/PrivateKey/KeyPair use source
lazy facades. Conversion to accepted arithmetic records is explicit. In particular,
asX509 PrivateKey conversion demands its public root; deferred callers must retain
the conversion thunk. It is not an implicit arbitrary-partial-value equivalence.

PublicKey/PrivateKey ordinary roots have lazy fields, KeyPair is a newtype root.
There is no invented validation or extra instance: only Public/Private derive
Generic, while KeyPair derives Data/Read/Eq/NFData. Public NFData forces n,e,size;
Private forces pub,d,p,q,dP,dQ,qinv. Show hides secrets, DebugShow reveals them.
Show/Read support source lazy character/list/projection protocols, with finite
String/ByteArray/BigInteger host bridges kept separate. Read preserves suffixes,
record order/precedence, numeric Int64 wrap and arbitrary Integer; no full-input
parse substitute. Generic metadata/product association are taken from the actual
installed .hi, not the unrelated pandoc StrictData schema. The crypto-local
Integer Data dictionary follows pinned OriginalData.hs and uses existing open
Data interfaces without modifying accepted shared code.

## Exact compiler/error boundary

CompilerProfile binds GHC9.12.2-O2, aarch64 Int64, crypton-2.0.1-inplace and
support_deepseq=true. The installed Types source matches pinned bytes. The .hi
and source/pointer-free observer scripts are retained for reproduction.

A deliberate two-bottom Generic Rep PrivateKey has different original exception
selection by context: root/show chooses rep:R; DebugShow chooses rep:LR. The .hi
uses depth-first products, while the optimized caller floats cases differently.
Control.Exception's installed documentation (verbatim original/Control-Exception.html)
identifies pure error/throw as imprecise exceptions: evaluation does not promise
which of multiple pending pure exceptions is chosen. All101 raw expected are
retained unchanged. Exactly99 comparisons require literal equality; two named
multi-bottom cases accept only the independently observed other-context witness
and are reported separately. Every single-fault and defined payload must match
exactly. No context-specific production API or universal error-order claim is
introduced. Initial row37 failure/draft/expected remain under history/.

The Eq draft originally forced the right root before unboxing left public_size;
original paired probes and actual .hi proved the selected GHC order. The new-only
facade/dictionary correction is retained with its failing baseline. Earlier Eq
capture used a JSON string for one Int-size control, so original Aeson defaulted
that control; the exact old capture/script is retained. Corrected numeric inputs
were independently recaptured, never adjusted from Kotlin. Two Data replay
adapter errors (unintended z demand and missing optional bad list) are tooling
history, not upstream bugs or changed expected values.

The immutable rejected JAR `51f1e090...` and all prior evidence remain under `/tmp/kotdoc-rsa-types-whnf-fix`; source/current pins and first failing row273 are retained in `history/pre-number-lexeme`. No old expected corpus was rewritten.
