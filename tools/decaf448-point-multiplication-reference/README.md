# Pinned Decaf448 multiplication and X448 engine

This checkpoint completes the remaining 17 definitions of pinned `ed448goldilocks/decaf.c`, following accepted geometry/tables commit `14bb1a158816f486b9a18d73a5f6ba4a61a3d4f9`. `SourceMatrix.json` retains all45 compiled definitions and their source lines. The header point-copy entry and conditional MSVC ctz implementation are accounted for by the earlier checkpoint. This does not complete local:613: Haskell X448/public/modern adapters, Ed448 SHAKE/signatures and the rest of the task remain open.

Production is specialized Kotlin and reuses the accepted field, scalar, geometry and literal table engines without modifying them. C and Haskell are development oracles only. Translated source retains Mike Hamburg/Cryptography Research copyright and the existing `licenses/decaf-MIT.txt`. The original archive lacks LICENSE; the provenance limits recorded by the accepted field checkpoint remain applicable.

## Profiles and independent expectations

Four native builds select field/API words32/32,64/64,64/32 generic, and actual host AArch64 NEON64/32. The forced32 cases select original source arithmetic on the host; they are **not execution on a real32-bit ABI**. Actual Haskell-linked crypton uses the fourth profile. NEON repeat-low32 mask behavior remains point-local and is inherited from the accepted geometry engine.

The extractor verifies original copies and mechanical transformations. Variant0 compiles unchanged C at O0/O2/O3; variant1 changes only the negative signed-shift expression described below; variant2 adds write/loop observations to that normalized copy; variant3 retains the original shift but returns a distinct sentinel immediately before the first negative-shift execution. Original expectations are never generated by Kotlin.

Every fixture preserves all allocated buffers including prefix/suffix guards and unused tails. Coverage includes0/1/n-1/n/n+1/2n-1/full448-bit scalar observations, canonical random values, identity/base/doubled/torqued/negated/rescaled points, five alias orders for dual/double outputs, input/output byte aliases, dynamically precomputed bases, invalid lookup indices, failed direct decoding with/without short-circuit, raw allow/short masks, zero/noncanonical X448 inputs, and all four original Curve448 literal KATs. Raw values beyond a public precondition remain observations, not portable mathematical API guarantees.

All original field writes are observed in order. A trace record is32 label bytes followed by16 little-endian uint64 words, zero-padded to160 bytes. The fixture contains its SHA256, write count, per-operation maximum limb and above-radix count. Kotlin reproduces that complete trace digest; selected loop checkpoints additionally retain full coordinates/scalar words. These are empirical caller-generated range observations through the actual multiplication/comb/wNAF/ladder families. They do not establish universal range safety or erase the accepted geometry non-tight32-bit counterexamples.

## Domains, aliases and source quirks

Batch inversion requires count>1 and nonzero product. Native assertion probes cover count1, zero product and all-zero precomputation; Kotlin checks the same internal failures. Input/output field arrays must remain disjoint where original `restrict` applies. Normalization consumes all zs before overwriting the Niels table, so its separately tested zs/table overlap preserves source ordering; zis stays disjoint. Niels lookup output is disjoint from its restricted table. Invalid indices produce three zero fields and leave the fourth untouched. wNAF table bits0..5 are tested; invalid shift counts, undersized buffers, invalid pointers and unbounded counts are outside defined C execution.

Point/scalar output aliases and byte aliases retain the actual source write order. Precomputed output/table overlap is retained as a raw memory-order observation: writes can corrupt later table reads and produce an invalid point; the independent group specification applies to disjoint table/output storage. Precomputation destruction clears exactly80×3 fields, preserving guards. Private prepare_wnaf_table writes its first entry even for tableBits0. Scalar2=0 makes base_double_scalarmul_non_secret return identity early, even if scalar1 is nonzero; this source quirk is preserved.

Direct multiplication returns the original decode failure. With nonzero short-circuit it leaves output unchanged; otherwise it substitutes the fixed base and still writes a multiplication result. No additional rejection is introduced. X448 performs all448 ladder rounds, clamps low2/high1 bits, serializes even when the resulting point is zero, and returns the source zero/nonzero status. Generate-key and derive-public-key preserve their source equivalence and input-copy behavior.

## Signed-shift boundary

Original recode_wnaf executes `current -= delta << pos` with signed int32 delta, which can be negative. This is ISO-C undefined behavior; source output at O0/O2/O3 is retained separately and is not promoted to an ISO-C portability guarantee. The normalized development observer replaces exactly that expression with unsigned subtraction of the safely bounded signed64 product `((int64_t)delta) * (((int64_t)1)<<pos)`. Kotlin implements this explicit intended extension. Independent integer reconstruction verifies every recoded scalar, odd digit bounds/order and sentinel. A separate original-expression observer stops before the first negative shift; Kotlin verifies both its full logical prefix and its partially written physical control array. Nonsecret multiplication inherits this boundary through its two recoders.

The integer verifier independently checks canonical scalar group operations in the Decaf quotient, the documented zero-variable source quirk, the RFC7748 X448 ladder and verbatim KAT results. It is a development proof over the finite corpus, not production arithmetic or a timing/memory-erasure proof. Original Ed448/Curve44829 examples run unchanged as a supporting native baseline; Ed448 signatures are not yet ported to Kotlin here.

## Reproduction

Run `python3 tools/extract-decaf448-point-multiplication-reference.py --check`, then `python3 tools/import-decaf448-point-multiplication-fixtures.py --verify-oracle`. The latter rebuilds all source profiles and comparisons, including assertion probes. Run `verify-math.py <corpus>` in this directory for the independent integer model. Build the Haskell executable using its pinned cabal.project/freeze, then run `verify-haskell.py --corpus <corpus> --oracle <executable> --check`.

Focused Kotlin verification is `./gradlew :core:test --tests io.heapy.kotdoc.crypto.CryptoDecaf448PointMultiplicationTest --no-build-cache -Dorg.gradle.vfs.watch=false`; packaging adds `:core:jar :cli:installDist`. Final XML and exact hashes are handed to the independent reviewer separately.
