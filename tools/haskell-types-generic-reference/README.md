# Original pandoc-types Generic reference

This is development/test tooling. Production traversal is Kotlin and never calls
GHC, Cabal or Pandoc. The four source functions are Text.Pandoc.Generic.bottomUp,
topDown, bottomUpM and queryWith in pinned pandoc-types1.23.1.2; syb0.7.4 supplies
everywhere/everywhere'/everywhereM/everything. Original syb Schemes/Aliases/Basics
and license, containers0.7 Seq source/license, and actual GHC9.12.2 Data/Typeable
interfaces are retained verbatim. Existing pinned Text/Map sources and licenses
are hashed too. Copyright notices in translated Kotlin are preserved.

`schema.py` extracts23 Definition Data declarations/77 constructors/five aliases.
`generate-schema.py` emits explicit source dictionaries. `generate-ast-bridge.py`
emits adapters from the existing explicit AST Show/Read constructor mappings;
those mappings are test inputs, never expected-output generators. All original
expectations below come from executing the pinned original Generic functions.

## Corpus and accounting

- core:26 source semantic predicates, including Haddock's distinct bottom-up and
  top-down normalization, list tails, State/List effects and query demand.
- constructor:92 inputs:84 unchanged original constructor/alias/Many expressions
  from the accepted original Read examples, plus8 explicit Unicode/surrogate,
  NaN/Infinity/negative-zero inputs. All77 source Definition constructors and both
  concrete Many specializations occur. The original input expressions are kept.
- target:644 variations over those inputs. Targets include Char, Text, Int, Bool,
  String list tails, Target's tuple alias (also matching Attr key/value tuples),
  Text key collapse and surrogate Char replacement before Text.pack.
- demand:33 original observations: caller-defined Data, constant root replacement,
  partial list tails/tuple fields, First/Last, Identity/Reader result laziness,
  Maybe first failure, default everything foldl order, and DefinitionList outer
  head/independent pair fields through the existing AST adapter. The Trace instance
  deliberately diagnoses parenthesization; it is not claimed to satisfy Monoid laws.
- deep:12 source cases/72 observations: source lists through20,000 and Emph trees
  through10,000, both pure traversals, State result/effect count and query counts.

There are807 source requests,808 JUnit cases including source integrity,7,360
result/effect/query comparisons through canonical and existing AST representations,
and4,463 Data/Typeable/field-order nodes. These counts describe different things.
No source-only rows are counted as Kotlin parity. Preserved-prefix hashes guard
all six initial core/constructor/target streams; fixtures are never generated by
Kotlin. Char State traces encoded as JSON String follow Aeson's Text.pack surrogate
replacement; integer Char queries separately retain exact source code points.

## Representation and demand

`GenericData.layer` supplies source immediate children and a reconstruction
function, not Kotlin reflection. Source lists expose head AND tail; tuple fields
are independent thunks; Map exposes one ascending list-of-tuples child; Text one
String child; Seq its viewl head/tail; Many one Seq field. StrictData fields in
Definition and newtype WHNF are modeled explicitly. Type aliases share a key,
newtypes do not. GHC TyCon List/Tuple2/Tuple3 spellings are exposed separately from
source syntax. Library keys normalize package names; build-specific installed
unit IDs are captured evidence, not a promised Kotlin TypeRep API.

Pure callback/input thunk overloads express ignored roots and fields. Ordinary
Kotlin callback arguments remain strict. GenericNode/GenericList/GenericTuple2/3
are source representations for partial values; existing AST records retain their
strict scalar fields, while list/map adapters defer independent fields where the
Kotlin types permit. No invented AST placeholder stands in for undefined values.

`GenericMonad` supplies lazy action/result thunks; the dictionary decides bind
and result demand. Included Identity, Reader and Maybe dictionaries execute the
original demand probes. WalkMonad overloads adapt strict finite State/List effect
sequencing with a persistent machine; the known Identity carrier uses its source
lazy identity adapter. No Walk traversal/query algorithm is reused. Query's
source everything foldl exposes the immediate gmapQ spine before its monoidal
result, even for First. Default custom monoids retain that order; lawful provided
Sequence/First/Last/Sum/Unit reductions preserve their demand with iterative walks.

The deep tests are finite executable bounds, not equivalence to a general GHC
heap, arbitrary callback stack, asynchronous exceptions or all infinite spines.
This minimal traversal protocol does not certify every Data/Typeable/GHC.Generic/
NFData class member. The full140 exports/350 instance-member/JSON supplement audit
and task611 remain open independently of this four-function checkpoint.

## Reproduction

Use the existing native build/toolchain (do not rebuild full Pandoc):

```
PATH=/tmp/kotdoc-haskell/ghc/bin:$PATH CABAL_DIR=/tmp/kotdoc-haskell/cabal-state /tmp/kotdoc-haskell/cabal build exe:types-generic-core-reference exe:types-generic-constructor-reference exe:types-generic-demand-reference exe:types-generic-deep-reference --project-dir=tools/haskell-types-generic-reference --builddir=/tmp/kotdoc-types-order-closure-build
python3 tools/haskell-types-generic-reference/verify.py --check-source
```

Each executable reads its corresponding `*-requests.jsonl` on stdin and emits
raw response JSONL. Constructor and target streams use the same executable.
`verify.py --core-oracle PATH --constructor-oracle PATH --target-oracle PATH
--demand-oracle PATH --deep-oracle PATH --ghc /tmp/kotdoc-haskell/ghc/bin/ghc`
replays every raw byte and the installed runtime interfaces without any build.
Gzip test resources decompress to these exact streams.

During isolated preparation, source hashes point at work-in-progress files.
After atomic installation they point at final core source/test/resource paths;
`--record` is an explicit author operation, never a test repair. Final Gradle and
independent-review results must be recorded in the durable porting matrix before
this draft becomes accepted evidence.
