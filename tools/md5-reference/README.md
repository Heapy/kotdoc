# Complete portable MD5 prerequisite for HMAC

Kotlin translates pinned crypton 2.0.1 `crypton_md5.c` and the shared hash-prefix
template. Original C/Haskell files are development oracles only. Production has
no native/JDK MD5 dependency. All eight source definitions are present: init,
update, finalize, finalize_prefix, private chunk/get_index/incr_sz/select_digest.
Seven shared mask helpers are also exercised. All 68 IV/K words, 64 message
indices and 64 rotations are checked directly against the original 64 R calls.

The ordinary native oracle includes unchanged source bytes. The separate
ObservedMd5.c adds only mechanically checked schedule/round snapshots after
the original macros, preserving their arithmetic. Expected observations are
captured from originals and never generated by Kotlin. The source compression
schedule is little-endian, including final bit-count and digest serialization.

* `capture-haskell.py --oracle /tmp/kotdoc-md5-haskell-oracle --verify` — 770

* `python3 tools/import-md5-fixtures.py --check` — packaged fixture bytes,
  constants/schedule and source/test bindings.

`CryptoMd5Hash` exposes immutable and mutable hash operations, Digest byte copy,
Eq/Ord/Show/Read and finite deferred carriers. Empty immutable updates preserve
context identity. Mutable finalize updates its context; reset reinitializes it.
Failure results in deferred carriers are memoized together with success. No
Digest Data reflection or universal Haskell-bottom/async/concurrency equivalence
is claimed. HMAC is the following active checkpoint, including all original
28 KAT assertions/14 properties, custom dictionaries and key/error/strictness
contracts. RSA padding/types/signatures, OS/SystemDRG, trust/chain and the
remaining task613/Pandoc/calibre goals remain open.

## Profile and domain boundaries

The actual native little-endian aarch64 C context is 88 bytes, while Haskell
allocates 96. Raw init preserves the final eight bytes and surrounding guards;
public context comparisons exclude that unspecified native tail. There is no
claim about uninitialized native heap contents, secure erasure or timing.
Generic chunk pointers are aligned; update's copy/alignment branch is exercised
at byte offsets 0,1,2,3,7. Invalid pointers, insufficient allocations and
memcpy-overlapping input/context are outside the supported raw domain. Defined
byte-output aliases include input and context buffer/state locations, retaining
source destructive effects. No other native ABI is claimed.

Words wrap modulo2^32, byte counters modulo2^64. Prefix lengths are source
uint32 conversions/clamps. Long positions preserve control arithmetic over the
entire valid JVM byte-array length domain: n<=len, padding1..64, end<=len+72,
without signed Int overflow. Real indexing narrows only after pos<len. The
virtual observer executes copied C control expressions without allocating or
hashing a 2 GiB buffer, so actual giant allocation/hash behavior is unproven.
The source ARCH_IS_BIG_ENDIAN conversion branch is represented mathematically
by explicit little-endian loads; an actual big-endian ABI run remains untested.
